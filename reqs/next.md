### ERROR-01 — No Auth Middleware (CRITICAL P0)

**File:** `middleware.ts` — **Does not exist**

**Impact:** Every single dashboard route (`/dashboard`, `/dashboard/products`, `/dashboard/sales`, etc.), plus `/analytics`, `/customers`, `/leads`, `/docs`, `/deployments` are completely accessible without logging in. Anyone with the URL can access your admin panel.

**Root Cause:** No `middleware.ts` file exists at the project root. Only `app/dashboard/products/page.tsx` has an individual `auth()` check. The other ~20 dashboard pages have nothing.

**Fix — Create `/middleware.ts`:**

```ts
import { auth } from "@/auth";
import { NextResponse } from "next/server";

export default auth((req) => {
  const { nextUrl, auth: session } = req;
  const isLoggedIn = !!session?.user;

  const protectedPaths = [
    "/dashboard",
    "/analytics",
    "/customers",
    "/leads",
    "/docs",
    "/deployments",
  ];

  const isProtected = protectedPaths.some((path) =>
    nextUrl.pathname.startsWith(path),
  );

  if (isProtected && !isLoggedIn) {
    return NextResponse.redirect(new URL("/login", nextUrl));
  }

  return NextResponse.next();
});

export const config = {
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico|images|public).*)"],
};
```

```ts
const isValid = await bcrypt.compare(
  credentials.password as string,
  user.password!,

if (isValid) {
  return { id: user.id, name: user.name, email: user.email, role: user.role };

```

```ts
// In seed / register action:
const hashed = await bcrypt.hash(plainPassword, 12)
await prisma.user.create({ data: { ..., password: hashed } })
```

### ERROR-04 — Register Form Does Nothing

**File:** `components/auth/RegisterForm.tsx` lines 44–52

**Impact:** The registration form has a fake submit handler — it waits 1.5 seconds and logs to console. No user is ever created.

```ts
// CURRENT — COMPLETELY BROKEN
const handleSubmit = async (e: FormEvent<HTMLFormElement>) => {
  e.preventDefault();
  setIsLoading(true);
  await new Promise((resolve) => setTimeout(resolve, 1500)); // FAKE!

  setIsLoading(false);

```

**Fix — Create `lib/actions/auth.ts`:**

```ts
"use server";
import { prisma } from "@/lib/prisma";
import bcrypt from "bcryptjs";

export async function registerUser(data: {
  firstName: string;
  lastName: string;
  email: string;
  password: string;
  department: string;
}) {
  const existing = await prisma.user.findUnique({
    where: { email: data.email },
  });
  if (existing) return { success: false, error: "Email already registered" };

  const hashed = await bcrypt.hash(data.password, 12);
  await prisma.user.create({
    data: {
      name: `${data.firstName} ${data.lastName}`,
      email: data.email,
      password: hashed,
      role: "TEAM",
    },
  });
  return { success: true };
}
```

### ERROR-07 — `AUTH_SECRET` Not Configured

**Impact:** NextAuth v5 requires `AUTH_SECRET` to be set in environment variables to sign JWT tokens. Without it, sessions will fail or be insecure in production. There is also no `.env.example` file in the repo to guide setup.

**Fix:**

```bash
# Add to .env.local
AUTH_SECRET="your-random-secret-here-32-chars-min"
```

```bash
openssl rand -base64 32
```

Create a `.env.example` documenting all required vars (see Section 4 for full list).

## 5. ⚡ Performance Optimization

The app has several patterns that will cause poor performance, especially on low-end Android devices common in the Kenyan market GTSS targets.

---

### PERF-01 — Entire Landing Page Is a Client Component

**File:** `app/page.tsx` line 1: `'use client'`

**Impact:** The entire homepage (Hero, Navbar, Features, etc.) is rendered on the client. This means:

- Zero SSR for the marketing page (bad SEO)
- Larger JS bundle sent to user before any content appears
- Poor Time to First Byte (TTFB) on slow networks

**Fix:** Remove `'use client'` from `app/page.tsx`. Only the components that need interactivity (Navbar with mobile menu, etc.) need `'use client'`. All others can be server components.

```tsx
// app/page.tsx — make it a Server Component
import {
  Navbar,
  Hero,
  TrustBar,
  Features,
  HowItWorks,
  Testimonials,
  CTA,
  Footer,
} from "@/components/landing";
// Remove 'use client' — static sections don't need it
```

---

### PERF-02 — 4 Animated Gradient Orbs on Every Public Page

**Files:** `app/page.tsx`, `app/(public)/layout.tsx`

Each orb is a 400–600px element with `filter: blur(80px)`, running two separate CSS keyframe animations simultaneously. On mobile devices this causes continuous GPU compositing on every frame.

```html
<!-- CURRENT: runs 8 simultaneous keyframe animations -->
<div class="gradient-orb gradient-orb-blue w-[600px] h-[600px]" />
<div class="gradient-orb gradient-orb-purple w-[500px] h-[500px]" />
<div class="gradient-orb gradient-orb-blue w-[400px] h-[400px]" />
<div class="gradient-orb gradient-orb-gold w-[300px] h-[300px]" />
```

**Fix:**

```css
/* Use contain: strict to isolate painting */
.gradient-orb {
  will-change: transform; /* already set ✓ */
  contain: strict; /* ADD THIS */
}

/* Reduce to 2 orbs max on mobile, use prefers-reduced-motion */
@media (prefers-reduced-motion: reduce) {
  .gradient-orb {
    animation: none !important;
  }
}
```

Also reduce from 4 orbs to 2 on mobile via responsive class logic.

### PERF-03 — `transition-colors duration-200` on Every DOM Element

**File:** `app/globals.css` line:

```css
@layer base {
  * {
    @apply transition-colors duration-200;
  }
}
```

**Impact:** The CSS `*` selector applies a transition to every element on every page. This forces the browser to maintain animation contexts for all elements and causes unnecessary style recalculations on interaction.

**Fix:** Remove this wildcard rule. Apply transitions only on elements that need them:

```css
/* Remove the global rule */
/* Apply targeted transitions where needed */
.btn,
a,
button,
input,
[role="button"] {
  @apply transition-colors duration-200;
}
```

### PERF-04 — Framer Motion Imported in 114+ Files

Every component imports from `framer-motion` which adds ~170KB gzipped to the bundle. Most uses are simple fade-in/fade-out animations that CSS can handle.

**Fix Strategy:**

1. Replace basic `opacity: 0 → 1` entrance animations with CSS `@keyframes`
2. Keep Framer Motion only for complex gestures, drag-and-drop, and layout animations
3. Use dynamic imports for pages that need it: `import { motion } from 'framer-motion'` → lazy loaded

```tsx
// For simple entrances, replace:
<motion.div initial={{ opacity: 0, y: 20 }} animate={{ opacity: 1, y: 0 }}>

// With CSS:
<div className="animate-fade-in-up">
```

Add to `globals.css`:

```css
@keyframes fade-in-up {
  from {
    opacity: 0;
    transform: translateY(20px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
.animate-fade-in-up {
  animation: fade-in-up 0.6s ease forwards;
}
```

### PERF-07 — No DB Indexes on Queried Fields

**File:** `prisma/schema.prisma`

Frequently queried fields have no database indexes. As data grows, these queries become exponentially slower:

```prisma
// CURRENT — no indexes
model Product { status String }           // Queried by: status in ['live', 'beta']
model Lead { status String }              // Queried by: status
model Customer { email String @unique }  // ✓ has unique index
model Transaction { status String }      // Queried by: status = 'Completed'
model Ticket { status String }           // Queried by: status
model PageView { path String }           // Queried by: path (groupBy)
```

**Fix — Add indexes:**

```prisma
model Product {
  @@index([status])
  @@index([priority])
}
model Transaction {
  @@index([status])
  @@index([date])
  @@index([customerId])
}
model Ticket {
  @@index([status])
  @@index([priority])
  @@index([productId])
}
model PageView {
  @@index([path])
  @@index([createdAt])
}
model Lead {
  @@index([status])
}
```

### PERF-09 — ViewTracker Writes to DB on Every Page Navigation

**File:** `components/analytics/ViewTracker.tsx`

Every route change fires `trackPageView(pathname)` which creates a `PageView` record in the DB. On a busy site, this creates enormous write load.

**Fix:** Batch writes or debounce:

```ts
useEffect(() => {

    trackPageView(pathname);
  }, 2000); // Only track if user stays 2+ seconds on page
  return () => clearTimeout(timeout);
}, [pathname]);
```

### DESIGN-02 — `font-display` Class Used But Never Defined

**Files:** `components/dashboard/DashboardLayout.tsx`, `app/(public)/layout.tsx`

```tsx
className = "font-display bg-slate-50 ...";
```

`font-display` is not defined in `globals.css` `@theme` block or any Tailwind config. This silently falls back to the default font, meaning a custom display font you may want to add later has no hook.

**Fix:** Either define it:

### DESIGN-06 — Mobile Menu Animation Uses `max-height` Transition (Janky)

**File:** `components/landing/Navbar.tsx`

```tsx
className={`transition-all duration-300 ${isMenuOpen ? "max-h-[500px] opacity-100" : "max-h-0 opacity-0"}`}
```

`max-height` transitions are notoriously janky because the browser has to calculate from `0` to an arbitrary max. The animation is uneven — it accelerates at the start and has dead time at the end.

**Fix:** Use Framer Motion `AnimatePresence` for the mobile menu (already used in Sidebar):

```tsx
<AnimatePresence>
  {isMenuOpen && (
    <motion.div
      initial={{ height: 0, opacity: 0 }}
      animate={{ height: "auto", opacity: 1 }}
      exit={{ height: 0, opacity: 0 }}
      transition={{ duration: 0.25, ease: "easeInOut" }}
      className="overflow-hidden md:hidden"
    >
      {/* menu items */}
    </motion.div>
  )}
</AnimatePresence>
```
